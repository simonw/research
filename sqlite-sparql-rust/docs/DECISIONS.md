- Base design: the correctness design's semantics framework (certain/maybe/safe_inject, GraphLoop, has_node rule, = matrix, aggregate rules, oracle). On top of it: speed's storage, cursor, planner toolbox and output surface, and engineering's build, API, transaction and crate discipline. This matches what all three judges recommended.
- Storage: one rdf_quad WITHOUT ROWID table (GSPO PK + full GPSO/GPOS/GOSP) plus 4 g-last partial indexes WHERE g<>0. Rejected correctness's full7 (75% more footprint) and engineering's 3-order default graph, which loses free merge joins: the perf judge measured merge 144-172 ms vs hash 387-611 ms on chain-2.
- New: rdf_gpox partial index (g,p,o,s) WHERE (o & 15) IN (5,8). With it, integer range pushdown is exact (INT range + numeric exceptions + residual FILTER) without stats/epoch guards or counters that plain-SQL writes can bypass. This addresses the semantic judge's flaw in both speed and engineering. Verified with EXPLAIN QUERY PLAN that SQLite uses it.
- Dropped ORDER BY-from-index: it can't be made exact without trusting kind statistics. TopK with an inline-int raw-payload fast path is used instead (estimated ~25 ms vs pyoxigraph 1.4 s).
- Ids: low 4-bit tag; inline INT, BOOL, DECIMAL, DATETIME, DATE, SHORTSTR under a strict format(decode(x))==lexical rule, pinned by encoding_version. DOUBLE/FLOAT are NOT inlined (canonical-form risk, low benefit). The codec is fully implemented in sq-core and tested (round trip + 30 non-canonical rejections + golden hashes).
- Blank nodes: counter ids (tag 2) from rdf_meta.next_bnode with no dictionary row (correctness), labelled b<hex>. TEMP ids carry the would-be tag; TermId::ERROR (tag 15) is the group-key sentinel, so an erroring GROUP BY key forms its own group as the spec requires, not merged with unbound.
- Cursor contract: speed's QuadCursor {width, fill, seek(&[..]), rebind}, with only free suffix columns and seekable/row-value templates. Made object-safe with 'static cursors (Box<dyn QuadCursor>) so a streaming sparql_rows execution can own its operator tree (Rc<dyn QuadStore>). A conformance suite lives in sq-core::testing and was verified against a brute-force store.
- Build: root workspace links the system libsqlite3 3.45.1 (rusqlite functions+vtab, no bundled); ext/ is a standalone workspace adding loadable_extension, with a compile-time SQLITE_VERSION_NUMBER<=3_045_000 assert plus cargo-tree and grep gates. Verified by building and loading the cdylib in the venv Python (3.45.1).
- C API allow-list restricted to the bindgen_3.34.1_ext symbols (verified by grep): no total_changes64, is_interrupted, changes64, vtab_in or rhs_value. Interrupts are detected by stepping a pooled SELECT 1; no progress handler, since it belongs to the user.
- Cache invalidation (missing from all three designs): connection caches are keyed by (dict_gen, schema_version), read in one pooled statement per entry. Only rows <= committed_max_row are cached, refreshed only when txn_state != WRITE, which makes rollback safe. Negative lookups are never cached across executions. Writes (own, foreign, unrelated tables) no longer flush the decode cache; the dictionary is append-only except sparql_vacuum_terms, which bumps dict_gen.
- Plan caching: only parsed spargebra::Query is cached (LRU 128). Lowered and physical plans are never cached because constants resolve against the current dictionary. This fixes engineering's stale-temp-id plan cache bug.
- Read transactions: SAVEPOINT sq_r{depth} when txn_state==NONE (verified 0 in a bare SELECT f()); reuse the outer transaction in xFilter (verified READ). Write scope: SAVEPOINT + bump write_gen first to take the write lock; ROLLBACK TO + RELEASE on error; refuse while sparql_rows cursors are open.
- Close hook: the eponymous sparql_status vtab's xDisconnect (Drop) finalizes the statement pool. Prototype verified: the WAL file is removed on close (no zombie), and the instance survives DDL, other connections' DDL and VACUUM. Re-arm check on every entry.
- Panic safety: every vtab method is wrapped in guard(catch_unwind), since rusqlite vtab trampolines don't catch (the judge saw Python abort with exit 134). Init and Drop are wrapped. RefCell with try_borrow and the never-hold-a-borrow-across-step rule replace a Mutex, avoiding self-deadlock when baseline SQL calls our UDFs.
- SQL surface: sparql_rows TVF with fixed n/v0..15/t0..15/id0..15/vars/json columns and col_used (verified: count(*) uses only the query column bit; col_used is passed via idx_str hex). sparql_view CREATE VIRTUAL TABLE with typed columns plus __term/__id hidden columns, pushed down as top-level sameTerm FILTERs (not a VALUES join, which would wrongly bind OPTIONAL-unbound rows). The writable rdf_quads vtab is deferred.
- No function is DETERMINISTIC: all depend on dictionary/database state (judge finding). Writers and filesystem functions are DIRECTONLY; sparql_config is registered per nArg so only the 2-arg setter is DIRECTONLY.
- GRAPH ?g push rule fixed: push only if the inner pattern is built from Bgp/Path/Join/LeftJoin/Union/Filter/Extend/Values/Graph, no expression mentions ?g or EXISTS, no Extend targets ?g, AND ?g is in certain(P') after pushing. Otherwise GraphLoop with a graph register stack (GraphSel::Active). GRAPH <c> checks dataset membership even with no inner patterns. This fixes graph-no-var, graph-from-named-*, bindings/graph and GRAPH ?g {}.
- safe_inject LeftJoin formula fixed to safe(L) ∩ (certain(L) ∪ ¬(vars(R) ∪ evars(f))), with the seed going to L only. Also defined for Minus, Filter, Extend (evars includes in-scope EXISTS variables), Distinct (certain only), Group (keys ∩ safe ∩ certain), and ∅ for Slice/GraphLoop.
- Filter placement: only downward, only within the group, only where all evars are certain, copied into Union branches, never into LeftJoin-right or Minus-right, never across Slice, never hoisted out of a group (filter-scope tests). TopK is never placed across Distinct.
- = matrix: correctness's Other/IllTyped separation (open-eq-07/08) plus engineering's NaN exception to the same-id fast path (only TYPED ids can be NaN, so other tags skip decoding). EBV of ill-typed boolean/numeric is false. STRBEFORE/STRAFTER keep arg1's tag on any match, including position 0 or an empty pattern.
- ORDER BY: a precomputed SortKey as a lexicographic tuple (class, family, primary with NaN-first f64 total order then rank then exact decimal, lex, datatype, lang). It is total by construction, so Rust 1.81+ sort_by cannot panic, and it agrees with < wherever < is defined (decimal vs double ties follow the spec's promotion to double).
- Aggregates: correctness's rules with AVG fixed (double when any float/double, decimal division otherwise, empty → 0). GROUP_CONCAT returns a simple literal (spec CONCAT of STR), not pyoxigraph's shared-lang extension.
- Hybrid SqlJoin (from correctness): maximal left-deep INL chains of plain quad patterns are rendered as one SQL statement with CROSS JOIN + INDEXED BY, so SQLite's VDBE runs OUR order at 0.55 µs/probe (verified EXPLAIN order). This closes the measured star-4 gap (our INL 50 ms vs SQLite 39 ms). The DP costs sqlable chains with vdbe_probe (recalibrated from 550 to 750 ns in the performance pass: SqlJoins over the benchmark databases measured 0.65–1.2 µs per outer row).
- Join toolbox (from speed): galloping MergeJoin (G=6 SQL, 10 DBR), factorized COUNT via Operator::fast_count, StarMerge only when cheaper, BindJoin with sorted/deduplicated probes and run reuse, and an adaptive switch to HashJoin at 8x estimate and 50K rows. Added an explicit SortBySlot enforcer for merge inputs (engineering measured scan+sort+merge 167-281 vs hash 387-611 ms).
- Cost model: hash build/probe split into small (<32K entries: 60/25 ns) and large (250/120 ns), correcting engineering's 0.06 µs underestimate (judge measured 0.33-0.65 µs/row incl. scan). Separate constants for SQL cursor, B-tree reader and memory; calibrated in WP14.
- Cardinality: characteristic sets + heavy-hitter (p,o) + per-predicate stats (speed), with runtime bounded counts capped at 1000 rows and 32 per query (engineering) to keep planning latency at or below about 2 ms. Statistics are hints only; correctness never depends on them.
- COUNT(*) pushdown: Op::Count uses fast_count — Scan → store.count() in the VDBE (~40 ns/row) only with no repeated variables, no range and a single graph; MergeJoin → factorized. This addresses the judge's note on repeated variables and merged graphs.
- Update semantics: one write scope per request; WHERE materialized before DELETE then INSERT; DELETE templates lookup-only; fresh blank nodes per operation; FROM NAMED-only gives an empty default graph; SILENT rules per spec. spargebra already lowers WITH/ADD/MOVE/COPY (verified in the parser source).
- Crate decomposition: 11 library crates + 2 tools + a separate ext. sq-exec depends only on core+expr; sq-results and sq-sqlgen depend only on core (via the new SolutionSource/TripleSource traits in sq-core); the oracle is its own crate, so the exec agent is not overloaded (feasibility judge). The update executor lives in sq-engine.
- Expression/exec decoupling: TermResolver and ExistsEval traits in sq-core, with Expr::Exists(ExistsId) referencing QueryPlan.exists / LoweredQuery.exists sharing the global slot layout. EXISTS is evaluated in SeedMode::Substitute, where Minus ignores seeded slots in the domain test and zero-length paths treat seeds as constants.
- Phase 2 only: the direct B-tree reader (sq-btree) behind the same cursor, with a kill switch and fallback, enabled only for rollback-journal file DBs with a held read lock and no write transaction. Budgeted at realistic 25-35 ns/row (judge: the fs::read prototype overstated it), with a leaf-pinning cursor. Not on the critical path.
- Verification performed for this spec (scratchpad/synth): sq-core compiles, 6 tests pass, clippy 0 warnings; a prototype sq-api + ext cdylib with sparql_status close hook and sparql_rows col_used builds in loadable mode, loads into Python 3.45.1, closes without a zombie, and survives DDL/VACUUM; EXPLAIN QUERY PLAN verified every template shape including partial indexes, row-value resume, capped counts and the CROSS JOIN SqlJoin order; the PRAGMA-function epoch query works; spargebra 0.4.7 enums (GraphPattern, Expression, Function, AggregateExpression, QueryDataset, GraphUpdateOperation) and rusqlite 0.40.2 vtab/function signatures (VTabCursor::column takes &self; best_index returns Result<bool>; col_used ungated; Module ctors const) were read from the registry sources.
